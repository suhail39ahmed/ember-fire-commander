# ember-web

**React + Vite + TypeScript PWA** (Firebase Hosting)

## Role

The EMBER web app serves two roles with a shared codebase:

1. **Volunteer PWA:** Push-to-talk voice interface, camera streaming, quick chips (*asap*, *api*, *aman*, *butuh bantuan*), task cards, mini-map, and WITHDRAW screen.
2. **Supervisor console:** Shared incident map, verification queue, approval controls, conflict resolution, downwind exposure corridor, and dispatch log.

Role-based routing determines which interface to show after Firebase Authentication.

## Architecture

- **Backend-mediated:** the browser talks only to `ember-api` (REST) and `voice-gateway` (WSS). No direct Firestore listeners, no direct Gemini calls.
- **Firebase Hosting:** global CDN serving the static bundle from `dist/`.
- **Firebase Authentication:** Google sign-in only (phone/SMS deliberately off).
- **Firebase App Check:** reCAPTCHA Enterprise (Fraud Defense) attestation, 6 h token TTL.
- **Firebase Cloud Messaging:** task and WITHDRAW push notifications.

## Phase 1 (current)

This is a **walking skeleton** with:
- Vite + React + TypeScript scaffold
- A landing page that calls `GET {VITE_EMBER_API_URL}/me` to verify backend connectivity
- Google sign-in placeholder (stub button, Firebase Auth integration coming in Phase 2)
- `.env.example` listing all `VITE_*` environment variables (no real secrets)
- `firebase.json` for hosting configuration
- `package-lock.json` (generated by `npm install`)

No secrets in the repo. The Firebase config values, App Check site key, Maps browser key, and VAPID key are public client identifiers, but are still kept out of Git and managed via `.env.local` or CI/CD environment variables.

## Local development

Prerequisites: Node.js 20+

```bash
cd apps/web
cp .env.example .env.local
# Edit .env.local with your Firebase config, API URLs, etc.
npm install
npm run dev
```

The dev server runs at `http://localhost:5173`.

To test the API connection, make sure `ember-api` is running locally on port 8080 (or update `VITE_EMBER_API_URL` in `.env.local`).

## Build

```bash
npm run build
```

The production bundle is written to `dist/`.

## Deployment

The `.github/workflows/deploy-web.yml` workflow builds the app and deploys it to Firebase Hosting. It is **manual dispatch only** and runs only from the `main` branch.

After this PR merges, a maintainer can:

1. Configure the required GitHub Actions variables (see the workflow file comments).
2. Trigger the workflow from the Actions tab.

The app will be live at `https://ember-fire-commander.web.app`.

## Environment variables

All `VITE_*` variables are public client identifiers that are baked into the bundle at build time. They are **not** server secrets.

| Variable | Purpose |
|----------|---------|
| `VITE_FIREBASE_PROJECT_ID` | Firebase project ID |
| `VITE_FIREBASE_AUTH_DOMAIN` | Firebase Auth domain |
| `VITE_FIREBASE_API_KEY` | Firebase web API key (public) |
| `VITE_FIREBASE_APP_ID` | Firebase app ID |
| `VITE_FIREBASE_MESSAGING_SENDER_ID` | FCM sender ID |
| `VITE_FIREBASE_VAPID_KEY` | FCM VAPID public key |
| `VITE_RECAPTCHA_ENTERPRISE_SITE_KEY` | App Check site key (public) |
| `VITE_MAPS_BROWSER_KEY` | Maps browser key (public, referrer-restricted) |
| `VITE_MAPS_MAP_ID` | Maps Map ID |
| `VITE_EMBER_API_URL` | REST API base URL |
| `VITE_VOICE_GATEWAY_WSS_URL` | WebSocket gateway URL |

See `.env.example` for the full list with defaults.

## Volunteer PWA (`/pwa`)

The volunteer screen lives in `src/pwa/` and is mounted at `/pwa` behind `RequireRole role="volunteer"`.

- Talks only to `ember-api` (`GET /digest`, `POST /observations`) and `voice-gateway`, as in `docs/contracts/shared-contract.md`. Every request carries `Authorization: Bearer <ID token>` and, when App Check is configured, `X-Firebase-AppCheck`.
- Errors use the contract envelope `{ "error": { "code", "message", "fields" } }`. A `400 validation_error` shows the field messages; network errors and 5xx can be retried.
- A report needs the phone's location (`lat`/`lng` are required). The client never sends an id or a severity.
- WITHDRAW is shown full screen when the digest carries an active `incident.withdraw` that names the volunteer, or a withdraw task.
- `VITE_API_BASE_URL` sets the API origin and falls back to `VITE_EMBER_API_URL`. `VITE_USE_MOCK_API=true` swaps in an in-browser mock with synthetic data.

Guide lives at `/pwa/guide`, with practice at `/pwa/guide/practice`. For Google sign-in during local testing use `http://localhost:5173` (not `127.0.0.1`). Mock mode still uses the normal Firebase sign-in, but Guide/practice data stays in the browser. Mock progress is stored per volunteer across reloads.

The Guide video uses the supplied YouTube fire safety training link. The backend can replace it through `TRAINING_VIDEO_URL`. Playback duration comes from the player; position resumes from device storage and syncs to `/training/progress`. YouTube playback requires a signal. The catalog stays readable offline, while practice shows “Chat needs a signal.” Live practice requires the agents Search datastore setup in `services/agents/practice/README.md`.

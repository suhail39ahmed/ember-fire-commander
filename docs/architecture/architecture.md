    conflicts/{cId}   {type(C_SEV|C_TYPE|C_LOC|C_STATUS), obsIds[], state(open|resolved), resolvedBy?, note}

  crews/{crewId}      {name, leadUid, memberUids[], stagingPoint?}

Rules sketch **[U, not tested in the emulator]**:
```
function role() { return request.auth.token.role; }
function inOp(op) { return request.auth.token.opId == op; }
match /ops/{op}/observations/{id} {
  allow create: if inOp(op) && request.resource.data.uid == request.auth.uid && role() in ['volunteer','lead'];
  allow read:   if inOp(op) && (role()=='supervisor' || resource.data.uid == request.auth.uid);
  allow update, delete: if false;                      // immutable; agents use the Admin SDK
}
match /ops/{op}/incidents/{id}  { allow read: if inOp(op); allow write: if false; }   // volunteers read a redacted view (see apps_summary §5)
match /ops/{op}/tasks/{id}      { allow read: if inOp(op) && (role()=='supervisor' || resource.data.crewId == request.auth.token.crewId);
                                  allow update: if inOp(op) && role()=='supervisor' || (resource.data.uid==request.auth.uid && request.resource.data.diff(resource.data).affectedKeys().hasOnly(['state'])); }
match /ops/{op}/audit/{id}      { allow read: if role()=='supervisor'; allow write: if false; }
```
Volunteers cannot read other volunteers' observations. A redacted `public_incidents` projection (written by the aggregator) is what phones listen to, so conflict internals and other villages' reports never reach a volunteer device.

**Realtime / shared state (backend-mediated).** Per the agreed rule the browser does **not** open Firestore listeners. ember-api / voice-gateway / ember-agents read and write Firestore (Admin SDK / gRPC); the PWA and console get updates over HTTPS REST and the Live WSS digest (and FCM for alerts). Offline: the PWA keeps an IndexedDB outbox and replays to ember-api when back online [U design]. Geo filtering stays server-side (geohash queries in the API/agents) [V geoqueries doc].

## 4. Aggregator / Fusion agent (ADK 2.0) — `ember/aggregator.py` [BUILT, 7 unit tests pass]

ADK 2.0 graph in `ember-agents`, triggered when a new `observation` document is written (Firestore trigger or Pub/Sub if latency demands). **Everything that decides is deterministic Python; Flash only reads photos and writes prose.**

| Stage | What it does | Rule / number (all [U] placeholders) |
|---|---|---|
| 1 Intake | Idempotent by `obsId`; uses `capturedAt` (not arrival time) so late offline reports merge correctly; **[not yet implemented, planned]** observations with GPS accuracy > 200 m would be kept as text only, not used for geometry | — |
| 2 Geometry | Observation with bearing+distance → estimated fire point; radius = max(GPS accuracy, 30 m) + 0.15 × distance. No bearing → observer position, radius = accuracy + 150 m | — |
| 3 Dedupe / cluster | Merge if `d / (r_obs + r_inc + 100 m) ≤ 0.6` **and** time gap ≤ 45 min. Ratio 0.6–1.5 → stay separate but flagged "possible duplicate" (C_LOC) for a human. > 1.5 → separate incident | tuned on a synthetic noise model (§7) |
| 4 Fusion | Link FIRMS lead if within incident radius + 1 km and ≤ 6 h old; a lead never confirms anything. Weather (wind) from the cached BigQuery/Open-Meteo values; Google Weather API is a live cross-check only | — |
| 5 Conflict | `C_SEV` flame levels differ ≥ 2 steps, or ≥ 1 step with the higher ≥ small; `C_TYPE` fire vs non-fire types; `C_LOC` possible duplicate; `C_STATUS` smoke/flame after a human set EXTINGUISHED | **Conflicts are flagged to a human, never silently resolved** |
| 6 Score | Evidence score 0–100 = 35 observers (min(1,(n−1)/2)) + 25 photo × Spotter confidence + 10 distinct viewpoints + 15 satellite link + 15 recency − 8 per open conflict. **Not a probability.** Status ladder: LEAD → REPORTED → CORROBORATED (≥ 2 distinct observers within 30 min, or photo + satellite) → VERIFIED / EXTINGUISHED / FALSE_ALARM (**human only**) | — |
| 7 Consolidate + Plan | Builds `digest/current` (≤ 400 tokens) and one instruction per crew: **WITHDRAW** (no approval; staging point 300 m along the wind-FROM bearing), **VERIFY** (observe-only; no approval), **DISPATCH_PROPOSAL** (supervisor approval). While a C_SEV/C_TYPE conflict is open, VERIFY goes out and the dispatch proposal is **held** | Calls `safety_rules.decide` |

**Safety under disagreement.** The highest severity reported wins for safety; only a human can downgrade it. Reports of large flame or wind ≥ 25 km/h with flame trigger R1 (WITHDRAW) regardless of other reports.

**Conflict handling table**

| Situation | System behaviour | Human step |
|---|---|---|
| Dedi: small flame; Joko: no flame, same spot | Incident keeps `severityMax=small`; C_SEV opened; dispatch held; VERIFY task to both ("wider photo, say if flame is visible") | Supervisor compares photos, resolves, may mark VERIFIED |

| Large flame from any one volunteer | WITHDRAW to all crews tasked near it, immediately, logged | Review after the fact; agency draft is never sent by EMBER |
| Volunteer asks to downgrade severity | Refused by rule | Supervisor only |

## 5. Per-volunteer Gemini Live sessions (cost-controlled)

Cost driver: one open Live session per volunteer re-bills the growing context each turn. My model [BUILT `cost_model_multiuser.py`, assumptions [U]]: **always-open mic ≈ $4.42 per volunteer-hour; push-to-talk bursts ≈ $0.093 per volunteer-hour (8 bursts)** — about 47× cheaper.

1. **Push-to-talk burst.** The phone holds a light WebSocket to `voice-gateway` while foregrounded. On press the gateway opens a Live session, sends `activityStart` (manual activity detection so engine/wind noise never triggers VAD [V capabilities page]); on release `activityEnd`/`audio_stream_end`. The session is closed ≈ 30 s after the reply.
2. **Shared context, not shared sessions.** At burst start the gateway sends the volunteer card (name, crew, current task) + `digest/current` (≤ 400 tokens) via `send_client_content(turn_complete=False)` [V]. The same call is made when `digest.rev` changes mid-burst. All volunteers therefore see the same picture from one aggregator-built digest.
3. **Write path.** The model calls `submit_observation(...)` (async, NON_BLOCKING); the **gateway** (not the model) writes the immutable observation with GPS from the phone. The model never computes distances, winds or scores and cannot change incident state.
4. **Stills go to Flash, not Live.** One compressed JPEG per report → Spotter (Flash) → structured result attached to the observation. Live receives the Spotter summary as text. No continuous video (avoids the 2-min A/V session cap and video-rate billing [V limits]).
5. **Things that never touch a model:** location pings, chips ("api / aman / butuh bantuan"), task acks, instruction cards, WITHDRAW.
6. **Caps:** per-user and per-op Live-minute caps in gateway code; supervisor can switch voice off (chips + text remain). Supervisor console is text-first with no Live session by default.
7. **Fallbacks:** Live unavailable → record a ≤ 10 s clip, queue it, Flash transcribes later [U]; read-out via on-device speech.
8. **Quota.** Gemini Developer API free tier lists 3 concurrent Live sessions; paid tiers publish only TPM limits and say concurrency is not guaranteed [S rate-limits search results]; Agent Platform PayGo documents up to 1,000 concurrent sessions per project [S https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/live-api/start-manage-session]. **Check before the 3-phone take that billing is attached.**
9. **Latency risk.** Opening a session per press adds setup time before first audio. Not measured; add "cold burst" to the plan §7 latency test and keep a 45 s warm-window option.

## 6. Authentication, roles, offline (summary; detail in `apps_summary.md`)
- Roles: volunteer, crew lead, supervisor, agency liaison (read-only), admin/dev.
- Gateway verifies the Firebase ID token on WebSocket upgrade; optional App Check (no-cost [V pricing page]).

## 7. Evidence and limits of what I measured
- Dedupe/conflict logic was stress-tested on a **synthetic** noise model of my own (GPS σ 15–60 m, bearing σ 15°, distance error 20 %, 300 scenarios; `ember/sim_multiuser_eval.py` → `data/sim_multiuser_eval.json`). At auto-merge ratio 0.6 / flag ratio 1.5: **precision 1.00, auto-merge recall 0.617, recall including human-flagged pairs 0.956, silent splits 4.4 % (65 of 1,472 true pairs); severity conflicts flagged 183/183.** Ratio 0.8: precision 0.99, recall 0.846; ratio 1.0: 0.979 / 0.944. These say nothing about real field noise.
- Demo scenario (`aggregator` run): 3 observers merge to ≈ 0 m of the true point; INC-1 CORROBORATED, evidence 87/100, C_SEV open, dispatch held, VERIFY cards to both; the 3.9 km report stays INC-2.

## 8. Honesty rules carried into the multi-user design
1. FIRMS hotspots are **leads to verify** ("thermal anomaly"), never "fires"; NASA's disclaimer says not for tactical use [V, plan §0].
2. No haze/plume/spread forecast; ranking and exposure labelled "indicative".
3. Hard safety rules in code (R1–R4); WITHDRAW needs no approval, dispatch always does; only humans verify/extinguish/downgrade.
4. Conflicts between reports are flagged to the supervisor, shown side by side, never averaged away.
5. Every number spoken or shown comes from a tool/database value (R6).
6. The persona and field session are **simulated**; no endorsement by YIARI/Power of Mama/agencies; EMBER never sends agency reports.
7. Location privacy (R10 update): supervisor sees exact positions; crewmates only within the same crew during an active op and only if the volunteer has not opted out **[U: decision for Suhail]**; no faces; TTL deletion.

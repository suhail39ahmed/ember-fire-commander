# Guide practice coach

`POST /internal/practice` is private to the backend service accounts through Cloud Run IAM. It has no incident tools or Firestore writes. The request is `{ message, lang: "en" | "id", lessonId?, index: 1..3 }`.

By default, Gemini receives all four authored text files in `guidance/` as trusted system context. The files are small enough to include in full, so practice does not require a separate search datastore. Responses and quizzes are generated by Gemini, not selected from fixtures. Review fire training copy with the content owner before production use.

Optionally set `VERTEX_SEARCH_DATASTORE` to `projects/PROJECT/locations/LOCATION/collections/default_collection/dataStores/DATASTORE` and import the four files there to use Vertex AI Search retrieval instead. A configured retrieval failure or model failure returns `503 practice_unavailable`; it never substitutes a canned answer.

The model uses the existing spotter Agent Platform client and `EMBER_FLASH_MODEL` / `EMBER_VERTEX_LOCATION` settings. The pinned google-genai 1.2.0 already includes `VertexAISearch` and `Retrieval`, so no SDK upgrade is required. Only validated, allowlisted JSON is returned. The API stores answer keys privately and grades checks; the client owns fixed safety wording.

The browser calls `POST /training/practice` on ember-api, which invokes this endpoint using its service identity. Answer keys remain private to the API, which grades answers and saves progress. Practice has no incident creation tools.

For live testing, set `VITE_USE_MOCK_API=false` in `apps/web/.env.local`, configure the API's `EMBER_AGENTS_URL` to the private agents service, and run the agents with valid Google Application Default Credentials and Agent Platform access. The dev server always uses port 5173. Setting `VITE_USE_MOCK_API=true` explicitly selects browser fixtures for the entire volunteer app, including practice, and never calls the agents.

For a local agents process, use `EMBER_AGENTS_URL=http://localhost:8082` in the API process and start `services/agents/app.py` with `PORT=8082`, `GOOGLE_CLOUD_PROJECT=ember-fire-commander`, and `EMBER_VERTEX_LOCATION=asia-southeast1`. Set up credentials with `gcloud auth application-default login` first. The API omits Cloud Run identity tokens only for HTTP loopback targets (`localhost`, `127.0.0.1`, or `::1`); all remote targets still require them. Environment values must be loaded into the corresponding processes; neither Flask app automatically loads the root `.env.local`. Restart the API after changing its environment.

Terraform supplies optional `practice_search_datastore`, enables Discovery Engine, and grants the agents service account its viewer role. Cloud Run needs an agents service deployment to pick up this change; no datastore is required for bundled guidance. Tests inject a fake model and do not call Google.
